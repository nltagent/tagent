# Справочник команд

Живой краткий список всегда доступен прямо в боте: `/help`. Здесь —
то же самое, но с пояснениями и примерами.

## 👥 Пользователи и доступ

Бот многопользовательский. Роли: **user** / **vip** / **creator**
(различие user/vip пока не используется — задел на будущее, обе роли
дают одинаковый доступ). Создатель — `OWNER_CHAT_ID` из `.env`, у
него полные права всегда.

Незнакомый `chat_id` при первом сообщении автоматически заводит
заявку на доступ и уведомляет создателя. Пока заявка не одобрена,
бот отвечает только статусом заявки.

| Команда | Кто может | Что делает |
|---|---|---|
| `/users` | только создатель | Список заявок и пользователей с ролями |
| `/approve <chat_id> user\|vip` | только создатель | Одобрить заявку |
| `/deny <chat_id>` | только создатель | Отклонить заявку |
| `/block <chat_id>` | только создатель | Заблокировать пользователя (без возможности снова написать боту) |

`/status`, `/selftest`, `/selftest_all` тоже доступны только
создателю — трогают инфраструктуру сервера.

**Все ключи — только свои.** Каждый одобренный пользователь (включая
VIP) обязан настроить собственные ключи: LLM-провайдер
(`/addprovider`), при необходимости — поиск (`/setsearchkey`) и
GitHub (`/setgithub`). Ключ из `.env` (профиль `default`) доступен
ТОЛЬКО создателю — у остальных нет отката на чужой или общий ключ:
без своего профиля любой вызов LLM/поиска/GitHub вернёт понятную
ошибку с подсказкой, что настроить.

## 📝 Заметки

| Команда | Что делает |
|---|---|
| `/note <текст>` | Сохранить заметку |
| `/notes [полностью]` | Показать заметки (по умолчанию обрезано до ~3600 символов; `полностью` — все, в нескольких сообщениях) |
| `/delnote <id>` | Удалить заметку по номеру |

## 🧠 Память и диалоги

| Команда | Что делает |
|---|---|
| `/remember <ключ>=<значение>` | Запомнить факт о себе/боте надолго (например, имя бота) — виден модели в любом диалоге |
| `/memory` | Показать, что помнит |
| `/forget <ключ>` | Забыть факт |
| `/history [полностью]` | История **текущего** диалога (по умолчанию сжато через LLM, если не помещается в одно сообщение; `полностью` — весь текст как есть, в нескольких сообщениях) |
| `/dialogs [все]` | Список диалогов (`все` — вместе с закрытыми) |
| `/newdialog` | Начать новый диалог |
| `/switchdialog <id>` | Переключиться на диалог |
| `/closedialog [id]` | Закрыть диалог (по умолчанию текущий); если закрыли активный — новый создаётся автоматически |

Самопамять (`/remember`) личная на каждого пользователя и общая на
все его диалоги; история и summary — отдельные на каждый диалог (см.
`docs/ARCHITECTURE.md`).

## 🔍 Поиск

| Команда | Что делает |
|---|---|
| `/search <запрос>` | Прямой поиск, в обход LLM |
| `/setsearch [keenable\|searxng]` | Показать/переключить свой провайдер поиска |
| `/setsearchkey <keenable\|searxng> <значение>` | Ваш личный API-ключ (keenable) или адрес инстанса (searxng) |

Модель сама решает, когда нужен поиск, во время обычного диалога —
запрос(ы) видны в ответе строкой `🔍 Искал: ...`. Ключ/адрес —
персональный: без `/setsearchkey` (кроме создателя, у которого есть
запасной вариант из `.env`) поиск вернёт понятную ошибку.

## 🤖 Модель

| Команда | Что делает |
|---|---|
| `/models` | Бесплатные модели (умный анализ через LLM, с кэшем) |
| `/models_free` | То же самое явной командой |
| `/models_free обновить` | Сбросить кэш и пересчитать |
| `/models_all` | Вообще все модели с ценами |
| `/setmodel <id>` | Переключить модель для ответов |
| `/usage` | Ваш расход токенов за сегодня (персонально, не общий на бота) |
| `/addprovider <имя> <base_url> <api_key> [модель]` | Добавить свой профиль агрегатора моделей — обязателен для всех, кроме создателя |
| `/providers` | Список ВАШИХ профилей (текущий помечен ➤) |
| `/setprovider <имя>` | Переключить активный профиль |
| `/delprovider <имя>` | Удалить профиль |

Профиль `default` (ключ из `.env`) виден и доступен только
создателю. Всем остальным нужен минимум один свой профиль через
`/addprovider`, иначе `/models`, `/setmodel` и обычный диалог с ботом
вернут ошибку с подсказкой.

## ⏰ Напоминания

| Команда | Что делает |
|---|---|
| `/remind <когда> <текст>` | Создать напоминание |
| `/reminders` | Активные напоминания |
| `/delremind <id>` | Удалить напоминание |

Форматы `<когда>`: `через 10 минут`, `через 2 часа`, `через 1 день`,
`завтра в 9:00`, `сегодня в 18:30`, `18:30` (сегодня, если время ещё
не прошло, иначе завтра), `2026-08-01 09:00`.

## 📊 Сервер

| Команда | Что делает |
|---|---|
| `/status` | Память, нагрузка, диск — прямо сейчас |
| `/selftest` | Живая самопроверка (быстро): реальные вызовы к LLM/поиску/GitHub-токену/базе/мониторингу |
| `/selftest_all` | Полная живая самопроверка: плюс cron/напоминания (ключевая диагностика "напоминание не сработало"), заметки и диалоги (создание/чтение/удаление), список моделей, и реальный round-trip в GitHub (если задан `GITHUB_TEST_REPO`) |

## 🐙 GitHub

| Команда | Что делает |
|---|---|
| `/setgithub <токен> [базовая_ветка]` | Ваш личный fine-grained токен (права Contents: Read and write) |
| `/pushcode <owner/repo> <ветка> <путь>` + код на следующих строках | Закоммитить готовый код в ветку (создаст её, если нет) |
| `/editcode <owner/repo> <ветка>` + пути файлов + `---` + инструкция | Модель сама переписывает файл(ы) по инструкции и пушит одним атомарным коммитом |

`/pushcode` и `/editcode` требуют личный токен, настроенный через
`/setgithub`. Исключение — создатель: если он не задал свой токен
командой, используется `GITHUB_TOKEN`/`GITHUB_BASE_BRANCH` из `.env`.
Без токена — понятная ошибка, навык просто выключен именно для вас
(у других пользователей со своим токеном он продолжает работать).

Пример `/pushcode`:
```
/pushcode myname/myrepo feature-x src/hello.py
print("hello")
```

Пример `/editcode`:
```
/editcode myname/myrepo feature-x
src/app.py
---
Добавь обработку ошибок в функцию main
```
